1 · RELATIONAL DATABASES
What is a relational database?
  • Stores data in tables made of rows and columns.
  • The relationship between each data point is clear, so searching is relatively easy.
  • The relationship between tables and field types is called a schema.
  • The schema must be clearly defined before the data is stored.
2 · POPULAR RELATIONAL / SQL
SQL and popular databases
  • SQL: Structured Query Language, used to query, update and create records.
  • SQL Server: Developed by Microsoft; rich interface and handles large data, but can be expensive.
  • MySQL: Free and open-source; used by Facebook and YouTube; struggles under too many operations.
  • PostgreSQL: Free, open-source and extensible; harder to set up for beginners.
3 · NON-RELATIONAL DATABASES
What is a non-relational database?
  • Any database that does not use the rows-and-columns tables of relational databases.
  • Its storage model is optimized for the type of data it stores.
  • Also known as NoSQL, meaning “Not Only SQL”.
  • Can use other query languages besides SQL.
4 · TYPES OF NoSQL DATABASES
Four storage models
  • Document-oriented: Pairs each key with a complex, JSON-like document.
  • Key-value stores: Each key holds one value, like a dictionary; one of the simplest types.
  • Wide-column stores: Tables of rows and columns, where column names can vary by row.
  • Graph stores: Nodes, edges and properties; ideal for connected data.
5 · POPULAR NoSQL DATABASES
MongoDB and Redis
  • MongoDB: Document store with JSON-like data, run over multiple servers with auto-sharding. Easy to set up; no joins.
  • Redis: Key-value store supporting strings, lists, sets and sorted sets. Easy to install; no joins; requires Lua knowledge.
6 · COMPARISON
Relational vs Non-Relational
  • Relational: Tables with a fixed schema, managed with SQL, with strong ACID guarantees.
  • Non-relational: Flexible models (documents, key-value, wide-column, graph) for semi-structured data, built for ease of use, scalability and availability.
  • In short: Choose the model that best fits the type of data you store.
